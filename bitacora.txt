  ### Justificación de controles del formulario

Día 2

Campo de fecha (`type="date")

control permite seleccionar la fecha del alquiler desde un calendario porque facilita el ingreso de la información y evita errores.

Lista desplegable

la lista desplegable es para el tipo de bicicleta porque el cliente tiene tres opciones: urbana, montaña o eléctrica. Esto evita respuestas diferentes a las que hay en el campo.

Botones de opción

Utilicé botones de opción para los planes de alquiler porque el usuario debe seleccionar solamente uno: 1 hora, medio día o día completo. Al compartir el mismo atributo `name`, se impide seleccionar varios planes al mismo tiempo.

Semana 2 - día 2: layout en 2 dimensiones
- Portada: Grid con 1fr y 1fr para texto e imagen. align-items: center centra el texto verticalmente.
- Galería Nuestras rutas: Grid con tres columnas iguales; gap separa las tarjetas.
- Reservas: Grid con 2fr y 1fr para formulario a la izquierda y contacto a la derecha.
- Documento y celular: Grid con dos columnas iguales para mantener cada etiqueta junto a su campo.
- Encabezado: Flexbox porque distribuye nombre y menú en una fila y los centra verticalmente.
- Pie: Flexbox porque distribuye los tres bloques en una fila, alineados por arriba.
- minmax(0, ...) permite que las columnas se reduzcan sin imponer el ancho mínimo del contenido.
- Se conservan fotos locales de referencia y enlaces relativos para GitHub Pages.

Semana 2 - día 2: mobile first (v1.5)
Los estilos base describen el móvil. Se usa min-width: 768px para tablet y min-width: 1200px para escritorio.
Problemas identificados al revisar el layout anterior y soluciones:
1. Portada, rutas y reservas mantenían varias columnas incluso con poco espacio. Ahora parten de una columna; la portada pasa a dos en tablet, las rutas a dos en tablet y tres en escritorio, y reservas pasa a 2:1 en escritorio.
2. El nombre del negocio competía con el menú por el ancho disponible. Ahora el header usa flex-direction: column y centra el menú en móvil; desde tablet vuelve a una fila. El footer también pasa de columna a fila.
3. Las tablas usaban display: block y overflow-x: auto, obligando a desplazarse lateralmente. Ahora tienen width: 100%, table-layout: fixed, fuente de 13px y relleno reducido en móvil; el texto puede ocupar varias líneas sin eliminar columnas ni datos.
4. Documento y celular quedaban en dos columnas demasiado estrechas. Ahora se apilan en móvil y recuperan las dos columnas desde 768px.
5. Se conserva max-width: 100% y height: auto en todas las imágenes para que no excedan su contenedor.

Matriz esperada según el CSS (no equivale a una prueba visual):
